## 7.14.0

- **Added: `/steer:work walkthrough <feature>` records a captioned
  walkthrough video of the running app from an approved intent.** It plans
  one scene per user-experience step, explores the app with the Playwright
  CLI, commits a re-recordable script under `scripts/demo/` with a
  `mise run demo:record` task and an anchored `/demo/` ignore rule, then
  checks the recording frame by frame on an ffmpeg contact sheet before it
  hands over the MP4. Node and Python starting points ship in
  `templates/demo/`, with captions, title cards, highlight rings, off-camera
  sign-in and one clip per persona. The README there says when to use the
  Playwright CLI, the MCP server or a committed script. (#777)
- **Changed: shareable pages start from Claude's Artifact types.** The PO
  questionnaire from `/steer:spec questions bundle` is now a Claude Doc the
  PO answers in place, with nothing to copy out or send back: pass its link
  to `/steer:spec intake clarify <doc-link>`, which exports it and absorbs
  the answers as before. Status reports, feature summaries, the release
  timeline and the capability menu render as Docs too, a status report as
  Slides when it will be presented, and audit findings and drift as a
  Dashboard, with the audit triage as a Doc that `/steer:work issues
  publish-audit <doc-link>` reads back. Where an account has no matching
  type or no Docs connector, the hand-written page still applies, and it
  may now load scripts from the Artifact tool's allowlisted CDN hosts at a
  pinned version, plus Google Fonts, where every external host was banned.
  Markdown stays a supported format in its own right, not only a fallback:
  ask for it (a reader without claude.ai, a file to attach) and every page
  renders as Markdown with the same content, saved to a temp file on
  request, and a filled Markdown questionnaire or triage goes back through
  the same `clarify` and `publish-audit` paths.
