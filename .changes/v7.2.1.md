## 7.2.1

- **Fixed: `ci:changelog` no longer asks for a fragment on a test-only PR
  with colocated tests.** The scaffold's `scripts/ci-changelog.sh` exempted
  `tests/` and `test/` directories but not test files living next to the
  code, so a Vitest or Jest repo adding only `src/foo.test.ts` failed the
  gate for a change that ships nothing. It now also exempts `__tests__/`,
  `__snapshots__/`, `*.test.*` / `*.spec.*` JS and TS files, and pytest's
  `test_*.py`, `*_test.py` and `conftest.py`. Non-code `*.spec.*` files such
  as `openapi.spec.yaml` still need an entry. Re-sync the scaffold with
  `/steer:setup sync` to pick it up (#661).
- **Fixed: `mise run changelog:new` and `mise run convert:doc` now work on
  Windows.** mise runs inline tasks through `cmd.exe` there, and both tasks
  used POSIX-only shell syntax: `changelog:new` failed on every Windows
  machine, and `convert:doc` handed uvx a single-quoted requirement it could
  not parse. `changelog:new` now runs `scripts/changelog-new.mjs`, which
  calls changie with no shell in between, so an entry body containing quotes,
  `&` or `|` survives. `convert:doc` switches to double quotes. Run
  `/steer:setup sync` to pick up both (#671).
- **Fixed: Dependabot auto-merge now approves only after every check has
  passed, and `/steer:setup protect` checks the setting it needs.** The
  shipped `dependabot-auto-merge.yml` approved first and then waited on
  required checks only, so a bump could merge while a non-required e2e job
  was still running or failing, and a skipped check read as green. The
  workflow now waits for every check, aborts on a failure or cancellation,
  requires each check in its new `GATING_CHECKS` list (`ci` by default) to
  actually pass, and merges pinned to the commit it verified. Its
  `GITHUB_TOKEN` approval needs "Allow GitHub Actions to create and approve
  pull requests", which was off by default and checked nowhere, so most bumps
  never merged. `policy/branch-protection.yml` now names that setting (schema
  4), and `/steer:setup protect` verifies it while the workflow is installed
  and enables it on confirmation, stating the trade-off: any workflow can
  then approve any PR. Run `/steer:setup sync`, then `/steer:setup protect`
  (#660).
- **Fixed: three reference passages still described the old Dependabot
  auto-merge gate.** `CAPABILITIES.md`'s dependency-automation Wired-when
  named the `github.actor` guard the workflow replaced with
  `pull_request.user.login`, so a sync checking it looked for a guard the
  template no longer has. `CONVENTIONS.md` and `/steer:setup protect`'s notes
  said the workflow waits only for the required `ci` check and that protect
  only enables Dependabot alerts. Both now say the workflow waits for every
  check and that protect also lets Actions approve PRs.
