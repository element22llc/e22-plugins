## 7.6.1

- **Fixed: `/steer:work review` batch approval no longer approves nothing
  under zsh.** The approval snippet split each `"<n> <sha>"` pair with
  `set -- $pr`, which zsh - the macOS default shell - does not word-split, so
  the SHA check compared against an empty string and every selected PR was
  reported "changed since review - skipped". The pairs now go through
  `while read -r n sha`, which splits the same way in sh, bash and zsh. A
  failed PR lookup or a failed approve is now reported as such, no longer
  as a changed PR.
- **Fixed: a finished skill now names itself in its closing heading, door
  and mode included.** Each skill's handoff step spells out its exact
  `## Recommended next actions - /steer:<door> <mode>` heading
  (`/steer:spec adr`, `/steer:setup doctor`, `/steer:audit code`), where it
  used to say only "emit a `## Recommended next actions` block" and runs
  closed on the bare door. The router rule now also says to keep a forked
  skill's heading when relaying its result, and to write it when the fork
  returned none: `/steer:status` reports came back with no attribution in 4
  of 6 eval runs.
- **Fixed: `/steer:standards` loads the rules in one batch, not one file per
  turn.** Reading each `rules/*.md` file in a round trip of its own cost
  about twenty round trips for a load that needs two. It now lists the
  directory once and reads every rule file, plus `plugin.json` for the
  version line, in a single parallel batch.
- **Fixed: a `/steer:status` report keeps its `/steer:status` attribution
  when relayed.** The skill runs forked, and the main session often rewrote
  the returned report with its own caveats, dropping the closing
  `## Recommended next actions - /steer:status` heading (2 of 3 eval runs,
  even after the router rule said to keep it). The report now ends with a
  one-line note telling the relaying session to pass it on unchanged,
  heading included.
