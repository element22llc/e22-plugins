## 7.17.0

- **Fixed: the intent template no longer says only `/steer:spec approve`
  fills the sign-off.** The `> Approved by:` / `> Approved at:` placeholders
  in `feature-intent.md`, and approve mode's ownership note, now name the
  one other write: `/steer:setup adopt` recording a feature already
  released as `live`, `Approved by: as-built`, with no `approved` step - as
  `ENUMS.md` already described.
- **Changed: adoption no longer asks the PO to approve shipped features.**
  `/steer:setup adopt` asks once whether the app is deployed with real
  users. A feature that already works there is written `Status: live`,
  `Approved by: as-built`, so it no longer waits on `/steer:spec approve` -
  shipped behavior has no scope left to approve, and the adoption PR review
  confirms the extraction. A feature on an undeployed app, one that is
  half-built or looks dead, or one with an open blocking question stays
  `draft` and keeps the PO approval gate. `/steer:status feature` labels an
  as-built intent's sign-off as released before adoption instead of
  missing.
- **Fixed: one TypeScript language server per scaffolded repo.** The
  scaffold's `.claude/settings.json` enabled
  `typescript-lsp@claude-plugins-official` next to steer's own `typescript`
  server, which claims the same extensions, so one of the two never started
  and registration order decided which. The scaffold no longer enables it;
  a `MIGRATIONS.md` entry has `/steer:setup sync` propose removing it from
  repos scaffolded earlier. Steer's `typescript` and `python` servers are
  unchanged and still need their binaries on `PATH`.
- **Added: `/steer:work debug` - root cause before the fix.** A defect now
  follows one procedure (`skills/work/modes/debug.md`): reproduce, trace back
  to where the bad value is produced, test one hypothesis at a time, state
  the causal chain with `file:line` before touching product code, then fix
  test-first at the source. Three refuted hypotheses or failed fixes stop the
  loop and go to the dev as a design question. `start`, `resume`, `finish`'s
  red-build fix and `--hotfix` follow it whenever the work is a defect;
  `debug <symptom>` with no fix asked is diagnosis only and needs no issue.
  Adapted from obra/superpowers `systematic-debugging` and Compound
  Engineering's `ce-debug` (both MIT); the prose is steer's own. A routing
  case `routes-root-cause-to-work` covers the new mode.
- **Added: `/steer:work qa` - diff-scoped browser QA before review.** An
  opt-in mode (`skills/work/modes/qa.md`) that maps the user flows the
  branch diff touches, adds the touched feature's acceptance criteria, and
  drives them in a real browser on a fresh local stack, edges included.
  Breakage this diff introduced is fixed through `debug` (cause, regression
  test, fix at the source); anything larger or pre-existing becomes a
  separate linked issue; the findings land in the PR's *Notes for the
  reviewer*. It reuses the walkthrough tool table (Playwright CLI with a
  shell, Playwright MCP without), commits no QA script, and never runs on
  its own: `finish` suggests it when the diff touches UI paths. Adapted
  from Compound Engineering's `ce-dogfood` (EveryInc, MIT); the procedure
  is steer's own.
- **Fixed: the hook scripts now pass `shfmt`, which gates them like every
  other shell script.** Six scripts under `hooks/` are reformatted (tabs,
  unindented `case` arms) with no behavior change, and the exemption that
  kept `shfmt` advisory for `hooks/` is removed from pre-commit and
  `mise run shell`.
