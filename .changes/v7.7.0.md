## 7.7.0

- **Added: best-effort Codex support through an `AGENTS.md` pointer.** Codex
  (and Cursor and Gemini CLI) read `AGENTS.md`, not
  `.github/copilot-instructions.md`, so they never saw the standards.
  `/steer:setup init` and `adopt` now add a short block to `AGENTS.md`. The
  block tells the agent to read the generated standards and `CLAUDE.md`, and
  explains how to invoke the `.agents/skills/` tree (`$steer-<skill>` in
  Codex). It is a pointer, not a copy: Codex truncates `AGENTS.md` at 32 KiB,
  and Copilot reads that file too. Steer owns only the text between its
  markers, so an existing `AGENTS.md` keeps its content. The
  `agent-surface-current` check flags a missing or stale block, and
  `/steer:setup sync` refreshes it in place. With the pointer alone, nothing
  injects the rules; no gate runs on Codex.
- **Added: steer installs as a Codex plugin and injects the rules there.** A
  new `.codex-plugin/plugin.json` loads the skills, and
  `hooks/codex-hooks.json` registers the existing rule injector at
  SessionStart, so a Codex session receives the same always-on rules as
  Claude Code. Install with `codex plugin marketplace add
  element22llc/e22-plugins` and `codex plugin add steer@e22-plugins`, then
  trust the hook in `/hooks`. Each part sets `additionalContextLimit: 0`, so
  Codex passes the rules through whole rather than spilling them to a file.
  Best-effort, like Copilot: no gate runs on Codex. The release stamps the
  new manifest's version with the others, and `check_plugin.py` fails on
  drift.
