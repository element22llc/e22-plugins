## 7.8.0

- **Fixed: cross-repo issues close on merge again.** steer told agents that
  GitHub closing keywords stop at the repo edge and had them write
  `Refs owner/repo#N` plus a manual close, so in a polyrepo member, or any
  repo with a separate tracker, a forgotten close left the issue open for
  good. A live test showed the qualified `Closes owner/repo#N` in a
  member PR closes the workspace issue when it merges into the default
  branch. `/steer:work`, `/steer:tracker-sync`, the PR template, the
  member note at session start and the polyrepo reference now write the
  qualified keyword. `/steer:tracker-sync close` remains only as the
  fallback when the issue is still open after the merge.
- **Changed: the scaffold's mise tasks use more of mise, and CI no longer runs
  the test suite twice.** The CI Coverage step re-ran every test because each
  workflow step is a separate `mise run`; it now passes `--skip-deps`, and
  `ci:deps` skips `pnpm install` while the lockfile and manifests are
  unchanged. `changelog:new` takes `--kind` / `--slug` / `--body` flags (the
  `KIND` / `SLUG` / `BODY` variables still work) and `convert:doc` a declared
  `<file>` argument, so `--help` documents both. Every root `mise.toml`
  declares `min_version`, `docker:up` times out after five minutes instead of
  hanging, and `ci:hygiene` runs `mise tasks validate`. `/steer:setup sync`
  carries existing repos forward.
