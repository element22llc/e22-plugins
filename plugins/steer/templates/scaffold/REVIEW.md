# Review instructions

How to rank findings when reviewing a pull request in this repo. Claude Code
Review and Copilot code review both read this file. The engineering standards
themselves are in `.github/copilot-instructions.md`, generated by the steer
plugin; this file only calibrates severity and scope.

## What Important means here

Important is for a change that would break behavior, leak data, or skip a gate
the standards require:

- A bug fix with no regression test that would fail without the fix.
- A behavior change with no test, or with no matching update to the owning
  `spec/features/<id>/contract.md`.
- Tests deleted, skipped or weakened to get CI green.
- A drift class the PR description does not flag: intent or contract drift, an
  undocumented behavior change, security-sensitive, compliance-impacting,
  operational (deploy, CI, infra), local setup or deployment changed, app docs
  invalidated, architecture or stack drift.
- A change to a high-risk area - auth and sessions, authorization, database
  migrations, `infra/`, secrets handling, deletion logic, billing, deployment
  and release logic - with no scoping in the linked issue, the contract or an
  ADR.
- A committed secret, credential or token, including in config or a test.
- A migration that is not backward compatible.
- An older image or tool major kept with `steer:allow-pin` and no ADR saying
  why.

Style, naming, comment density and refactoring suggestions are Nit at most.

## Cap the nits

Report at most five Nits per review.

## Do not report

- What CI already enforces: lint, formatting, type errors, the version-pin
  check.
- Generated files: lockfiles, `CHANGELOG.md` (assembled from `.changes/`),
  `.github/copilot-instructions.md`, `.github/instructions/`,
  `.github/agents/`, `.agents/skills/`.
