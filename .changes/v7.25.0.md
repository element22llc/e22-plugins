## 7.25.0

- **Fixed: the scaffold no longer allows `Bash(sh *scripts/issue-body.sh*)`.**
  Its leading wildcard also matched `sh -c '<anything>' scripts/issue-body.sh`,
  so any command could run unprompted. No anchored form exists (the plugin
  path is machine-specific), so the entry moves to `permissions.ask`. On
  `/steer:setup sync`, the existing permission-tier dedupe then removes the
  exact copy releases 7.22 to 7.24 put in a repo's `allow`; a hand-edited
  variant is left alone. When `/steer:work` reaches `update-state` through
  `/steer:tracker-sync`, the `issue-body.sh` run now asks first. A new
  `check_standards.py` guard rejects any scaffold `allow` entry that is bare,
  all-wildcard, or has a wildcard before its fixed command tail.
- **Fixed: skills keep a legal path on a host that ships only `skills/`.**
  The Copilot app on a remote host (WSL) has been seen to load steer's
  skills and agents without `scripts/`, `templates/` or `hooks/`, leaving
  every bundled helper and reference doc a skill names missing. The router
  rule now says how to degrade: read a missing file from the public repo's
  `main` branch, treat a missing helper as failed (the skill's no-helper
  path, else its failure path), and never run a helper fetched from a URL. The `tracker-sync`
  `update-state` op gains a no-helper arm that writes the issue body by
  hand under the same fetch-compare-write guard. A standards check pins the
  fallback URL and the no-helper arm (#944).
- **Changed: the skill listing fits a 200K-window session again.** The 29
  `description` + `when_to_use` entries had regrown to 8,220 characters,
  103% of the 8,000 a 200K-context model gets, so Claude Code could drop
  whole descriptions, least-invoked skill first, before any other plugin's
  skills were counted. The listing is back to 7,787 (97%). `work`, `next`,
  `status`, `audit`, `standards` and `setup` lost restatement between the
  two fields and enumerations the skill body carries; every quoted user
  phrasing, guardrail phrase and routing-fixture keyword is kept. No
  description holds a `<placeholder>` or `->` any more: Claude Code shows
  them to the model as `&lt;`, `&gt;`, and the skill body and
  `argument-hint` carry the placeholders (#961).
- **Fixed: the per-call hooks no longer re-probe jq on every field read.**
  The jq probe's cache was set inside each `$(steer_field ...)` subshell and
  died with it, so the Bash and write hooks spawned `jq --version` two or
  three times per call - about 40 ms each where jq is a mise shim. The five
  PreToolUse/PostToolUse hooks now probe once per run, and
  `check-bash-actions.sh` exits before any jq spawn on a command that names
  no `gh`, no `git` + `push` and no MCP tool, taking a plain Bash call from
  about 170 ms to about 10 ms on macOS. The hook suite counts the probes,
  and the latency test now budgets each per-call hook's fast path (1 s by
  default, `STEER_HOOK_CALL_BUDGET_MS`) next to the SessionStart chain
  (#966).
- **Changed: the plugin download no longer carries the hook fixture suite.**
  An install copies the whole plugin directory, and the POSIX-sh hook tests
  (about 328 KB, 9% of the plugin) were in it though no session reads them.
  They now live at the repo root under `tests/hooks/`. The eval suite and
  the mod test stay: `claude plugin eval` and `claude plugin test` refuse
  files outside the plugin directory (#964).
- **Changed: Dependabot now groups security updates too.** A `groups` entry
  without `applies-to` covers version updates only, so each security alert
  opened its own PR and waited for its own review. Every ecosystem block in
  the shipped `dependabot.yml` gains a `security` group
  (`applies-to: security-updates`, minor + patch); a security major still
  arrives alone, so it never holds a grouped bump back from auto-merge. The
  `docker` and `terraform` blocks gain the `minor-and-patch` group they
  lacked, and `docker` scans `/` and `/apps/*`, where the scaffold puts each
  app's `Dockerfile`. `/steer:setup sync` proposes the same edits to an
  existing `dependabot.yml` (MIGRATIONS). The review gate is unchanged: a
  repo whose protection requires a review still approves each grouped PR.
- **Fixed: the merge gate no longer times out on a large Bash command.**
  `check-bash-actions.sh` parsed the command one character at a time, and
  macOS awk copies the whole string on each step, so a 400 KB command took
  10 to 30 s against the hook's 10 s timeout - and a timed-out PreToolUse
  hook lets the command run, `gh pr merge` included. The parser is now
  linear (about 1 s for 400 KB), runs once per call instead of once per
  check, and runs in the C locale, so accented text no longer aborts it.
  Past 512 KiB, on a U+0001 byte, or when the parse fails, the gates match
  the raw command with quotes, backslashes, newlines and `=` opened to
  spaces, so quoted prose counts there too - failing closed. A latency
  test denies eight large command shapes inside half the timeout (#966).
- **Changed: `work`, `protect` and `questions` regain headroom under the
  compaction re-attach cap.** All three rendered at 97-100% of the 20,000 ch
  cap, so the next fix to any of them would have failed `mise run check`.
  Procedure now lives in sibling files read just-in-time, and every
  guardrail stays in `SKILL.md`: `protect` gains `RULESETS.md` (schema 7
  rulesets) and `SOLO-TRUNK.md` (the graduation-signals report), and its
  graduation write steps join `APPLY.md`; `questions` gains `FOLD.md` (step
  6's per-answer mechanics, with the tier gate kept in place); `work`'s
  subcommand table becomes a mode map, and its marker and queue mechanics
  move into `WORK-MARKER.md` and `modes/queue.md`. They now render at
  82-84% of the cap (#967).
- **Added: interviews now hold the human's words to the glossary and the
  code.** `QUESTION-ROUNDS.md` gains a "Language and code" section that every
  interviewing skill inherits (`/steer:spec`, `/steer:questions`,
  `/steer:build`, `/steer:setup` and its `adopt` pass, the ADR stress test,
  `/steer:work issues brainstorm`). The session reads `spec/glossary.md`
  before the first round, then asks, inside the normal rounds and with a
  recommended answer: about a term that conflicts with the glossary, about a
  fuzzy word that needs one canonical term, about a concrete edge case that
  forces the boundary between two concepts, and about a claim the code
  contradicts - phrased as product behavior for a PO. A resolved term is
  written to the glossary in the same turn, in the main product language
  with its English code identifier; renaming code to match stays a
  `/steer:work` change. A new e2e eval, `e2e-glossary-term-challenged`,
  checks that a paid "cart" is challenged against the glossary's Cart.
- **Fixed: the re-listed `frontend-design` plugin follows its upstream move.**
  Anthropic deleted `plugins/frontend-design` from `anthropics/claude-code`
  and develops it in `anthropics/claude-plugins-official`; the marketplace
  pin still resolved, but no newer SHA of the old repo held the path, so the
  plugin could not be updated. The pin now points at the new repo (plugin
  1.1.1), and the design-sources reference describes the reworded skill
  instead of quoting lines it no longer contains.
- **Fixed: the subagent-digest hook's header comment.** It carried a broken
  sentence and claimed a ~60k-character payload; it now reads cleanly and
  points to `check_context_budget.py --report` for the current size. No
  behavior change.
