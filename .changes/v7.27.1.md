## 7.27.1

- **Fixed: `contract.md` no longer carries a `Last updated` line.** Every PR
  touching a contract rewrote that one header line, so any two open PRs on
  the same feature conflicted, and the line tended to grow into a change log
  the contract is not meant to hold. Git already records when the file
  changed, and the PR's Spec delta records what changed. Existing contracts
  keep the line until a dev deletes it; nothing reads it.

- **Fixed: follow-up work on a ready PR is pushed once per round, not once
  per commit.** Every push to a ready PR or the solo-trunk `main` runs the
  whole CI pipeline on billed runner minutes, and agent sessions were pushing
  each fix as they committed it, in chains minutes apart. Rule 45 now says
  so, and `/steer:work finish` defines the round: the work one message from
  the dev or one review asks for, each fix committed, the local gates green,
  then one push at the end of that turn - never held for asks not yet made.
  A `/steer:work drive` worker pushes once after addressing every review
  point, and one that runs out of budget pushes only green commits, never a
  WIP checkpoint to a ready PR.

- **Fixed: a push that cannot wait for the end of a round no longer runs
  CI on a ready PR.** When a session must push before its round of fixes is
  done (work it cannot keep local), `/steer:work finish` now moves a PR it
  readied earlier in the same conversation, with no review submitted since,
  back to draft first (`gh pr ready --undo`), so that push costs no runner
  minutes. At the end of the round it pushes the last commits and readies
  the PR again only if it still qualifies; otherwise it stays a draft for its
  author. Any other ready PR - one a human, a spawned worker or an earlier
  session readied, or one under review - stays ready and gets only green
  commits, once. The exploratory push for a CI-only failure never
  re-drafts, since it needs the run.
