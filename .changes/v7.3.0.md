## 7.3.0

- **Fixed: Dependabot auto-merge no longer bills a runner to wait for CI.**
  The shipped `dependabot-auto-merge.yml` looped `gh pr checks` and
  `sleep 30` on a hosted runner for up to an hour, so every Dependabot PR
  paid for the whole CI run a second time in idle minutes. The job now
  approves the bump and arms GitHub's native auto-merge, finishing in
  seconds, and branch protection's required checks decide when it merges.
  It refuses to arm unless every check in its `GATING_CHECKS` list (`ci` by
  default) is required on the default branch, so a bump still never lands
  on red or unprotected CI. A non-required check, such as an e2e job, no
  longer holds the merge: require it to gate. Native auto-merge needs the
  repo-wide "Allow auto-merge" setting, which offers the button on every
  PR without loosening any PR's protection. `policy/branch-protection.yml`
  now sets `allow_auto_merge: true` (schema 5), and `/steer:setup protect`
  verifies it and the required checks while the workflow is installed. Run
  `/steer:setup sync`, then `/steer:setup protect` (#687).
- **Added: a steer status band above the prompt, and `/steer_snapshot`.** In
  the Claude Code terminal and the Desktop Code tab (v2.1.287 or later), a
  managed repo now shows one dim line above the prompt with steer state only:
  delivery mode, feature and draft counts, open questions, ADRs awaiting
  ratification, work claims, and unfiled steer faults (pointing at
  `/steer:report`) - nothing the status line already shows. It refreshes
  at session start, after each turn and when the working directory changes,
  and stays hidden in a repo with no spec spine. `/steer_snapshot` prints the
  full workspace snapshot at once, with no Claude turn, even while Claude is
  working. Both are a read-only mod (`hooks/register.tsx`) over
  `scripts/workspace-snapshot.sh`, whose new `--brief` mode prints the band's
  counts. They enforce nothing: every gate stays in the shell hooks. Both are
  Claude Code only: GitHub Copilot (CLI and VS Code) loads no mods. Other
  Claude Code surfaces (the VS Code panel, `claude -p`, cloud sessions) run
  the mod's refresh but draw no band; older Claude Code versions and
  organizations that allow only managed mods skip the mod and keep every
  existing hook.
- **Changed: `/steer:work` runs the local gates before it pushes, so CI
  runs once per change.** `finish` pushed, opened the PR and then fixed a
  red build by pushing again, so every fix attempt paid for a full CI run on
  billed runner minutes - in an agent-heavy repo that alone can exhaust the
  Actions budget. `finish` now runs the fullest local gate `mise tasks`
  offers (`mise run ci`, else `mise run check`, else lint, typecheck and
  tests) until green before any push, and sends an earlier checkpoint push
  to a draft PR, which CI skips. On a red build it reproduces and fixes the
  failure locally, then pushes once with every fix batched; only a failure
  that reproduces solely in CI earns an exploratory push. A hotfix runs the
  same local gates but opens its PR ready. Rule 45 carries the one-line
  principle: CI confirms, it is not the loop you iterate in (#689).
- **Fixed: the shipped `ci.yml` runs its advisory checks in one job, not
  three.** `design-lint`, `spec-drift` and `ai-slop` each ran as their own
  job on their own runner, and GitHub bills every job rounded up to a whole
  minute, so three checks that take seconds cost three billed minutes on
  every push to a ready PR. They are now steps of a single `advisory` job
  with one checkout. Each step still continues on error and writes its own
  summary and annotations, `spec-drift` still runs on push to `main` (the
  only drift signal in solo-trunk), and the job still shows red when a check
  fails without blocking the merge. Run `/steer:setup sync` to take the new
  job (#688).
