## 7.19.0

- **Changed: the review fix loop keeps going while it converges.** The
  plan gate and the `/steer:work finish` code gate stopped after 2 rounds,
  even when round 2 was still cutting the confirmed high findings. Now a
  round with no high finding ends the loop, another round runs only while
  that count strictly drops from the round before, and the hard cap is 4
  rounds (`REVIEW-LOOP.md` section 2). A round that finds as many or more
  stops it as churn. `/steer:work queue` and the `/steer:loop` workflow
  template follow the same rule.
- **Changed: High-risk work gets the plan gate without `--reviewed`.**
  `/steer:work start` now classifies the change, and one in a High-risk
  area runs the independent plan review before any code, as if
  `--reviewed` were passed (`--hotfix` excepted). The plan sign-off is
  the dev scoping High-risk work already required, asked against the
  vetted plan when the dev is in the session; with no dev present, scope
  recorded on the issue stands in, and without it the work stops and asks
  for scope on the issue. Pre-production work skips the sign-off.
- **Fixed: the gates reference names the dev as the High-risk plan
  sign-off decider.** `/steer:reference gates` still said the plan
  sign-off is decided by whoever asked for the work, even on the new
  High-risk `start` path, where `/steer:work` asks it of the dev as rule
  `60-high-risk`'s scoping.
