## 6.6.0

- **Change size is now change classification: Trivial, Behavioral,
  High-risk.** The old model sized a change by line count - Tiny under ~20
  lines, Small under ~200, then Medium and Large - and line count is the one
  property that says nothing about what a change can break. A 12-line auth
  edit read as Tiny; a 400-line rename read as Large. Rule
  `80-change-size` is now `80-change-class` and classifies by **what the
  change does**: Trivial is no observable behavior change and the PR is the
  work record; Behavioral is observable behavior changing for a user, caller
  or operator, and carries tests plus the owning `contract.md` in the same
  PR; High-risk is the rule 60 list at any size. An arguable class still
  takes the heavier one, and a choice costly to reverse still takes an ADR in
  any class.
- **Issue-first names the two cases that need an issue instead of a size
  threshold.** In a GitHub-adopted repo an issue is required before the first
  mutation for **High-risk work** and for the **six value cases** - a planned
  feature, a tracked bug, work spanning more than one session, work
  coordinated between people, a product decision or acceptance to record, or
  a discovered follow-up. Everything else - a Trivial change, an ordinary
  fix nobody is tracking, spec edits, documentation, generated output,
  lockfiles - lets the **PR be the work record**. This is a relaxation: the
  rule previously reached every implementation-affecting mutation above Tiny.
  The two advisory hooks (`check-write-nudges.sh`, `reconcile-issue-first.sh`)
  follow the new wording; both still only report, and neither blocks. The
  router and commit-autonomy rules stated the retired universal form - "work
  find-or-creates the issue", "the first mutation presupposes an active
  issue" - and now both say "where Issue-first requires one", so no rule
  contradicts the relaxed one.

- **Five rules leave the always-on payload.** Housekeeping, context hygiene,
  Artifacts and design sources no longer ship in every session's SessionStart
  context: each was already owned in full by a reference document
  (`HOUSEKEEPING.md`, `CONTEXT-HYGIENE.md`, `ARTIFACTS.md`,
  `DESIGN-SOURCES.md`) and by the skill that loads it - `/steer:tidy` for
  housekeeping, every rendering skill for Artifacts, `/steer:reference` for
  the other two. The router gains one short paragraph naming what moved and
  where, so the model routes there instead of improvising, and keeps the two
  context lines that bind no particular skill: delegate a heavy sweep and
  bring back the result, and route a durable fact to its home on disk rather
  than offering to keep it in private session memory. The spec rule keeps a
  short UI paragraph pointing at `/steer:reference design-sources`.
- **Rule `53-autonomous-loops` is now opt-in.** It carries
  `inject-when=automation-optin`, a new scope predicate that is true only when
  the consumer repo declares `policy/automation.yml` with `loops: true`. It is
  the one predicate that fails **closed**: the rule governs machinery a repo
  only has once it has asked for it, so a repo running no loop pays nothing
  for the rule. `/steer:loop scaffold` now writes that declaration alongside
  the workflow, `verify` reports it as a gap when missing, and `remove` drops
  it. An e22 app repo's always-on payload falls from 66,026 to 58,412
  characters; a knowledge folder's from 27,060 to 24,827.

- **The house stack is now an org pack a repo can decline.** Rules
  `10-stack`, `12-stack-infra` and `15-commands` named one organisation's
  tools - Next/TS/Tailwind, Drizzle, OpenTofu on AWS, pnpm/uv, SSM Parameter
  Store - and shipped to every managed repo whether or not it was on that
  stack. They are now the **e22 org pack**, selected by `policy/org.yml`'s
  `pack:` key through a new `org-e22` scope predicate. An **absent** file
  reads as `e22`, so an existing repo receives exactly what it did before;
  declaring any other value drops the pack. A migration-ledger entry seeds
  the file on `/steer:sync` so the choice becomes visible and editable.
- **The core rules name no vendor.** Secrets handling says deployed secrets
  live in "the declared store" - the org pack's, or an ADR's - instead of
  naming SSM Parameter Store; the baseline patterns rule states each pattern
  as a principle and the pack carries its default-stack instances (TS
  `strict`, Drizzle Kit, Server Components, Sentry, the lockfile set). Both
  moved into `10-stack`, along with the deployed secret-store default.
- **`inject-when` markers compose with `&` for AND.** `12-stack-infra` needs
  "does IaC **and** follows the pack", which the existing `|` (OR) could not
  express. AND binds loosest, so `a&b|c` reads as `a AND (b OR c)`. Payload
  for a repo that declares another pack: 58,820 -> 52,660 characters; an e22
  repo is unchanged by design (58,412 -> 58,820, the cost of stating the pack
  boundary in the rule).

- **Five rules about finishing a change become one.** `50-definition-of-done`,
  `51-verify-loop`, `55-drift-gates`, `75-compliance` and `99-end-of-session`
  are now `50-done`, with the Definition of Done up front and Verify loop,
  Drift gates and the End-of-session checklist as sections under it. The five
  DoD items, the drift-class list the scaffold's PR template mirrors and every
  checklist item are carried verbatim or tightened, and those three headings
  keep the names other rules and skills already cite. `75-compliance`'s
  "Audit-aligned delivery" heading does not survive the fold: its
  SOC 2 / ISO 27001 paragraph is now unheaded text inside Drift gates, and the
  evidence-chain list it carried is left to `TRACEABILITY.md`, which holds it
  in full. A cross-reference now reads
  `` `50-done` § Drift gates ``. An e22 app repo's payload: 58,820 -> 56,234
  characters.

- **Secrets handling folds into high-risk; hotfix folds into gates.** Secrets
  were already declared a high-risk area by the first line of their own rule,
  so `70-secrets` is now `60-high-risk`'s *Secrets handling* section - the
  never-commit rule, the local `.env` bootstrap and "deployed secrets live in
  the declared store", unchanged. `62-hotfix` becomes `61-gates`' *Hotfix /
  incident fast-path* section: the objective entry condition, what the lane
  relaxes (ceremony and ordering, never authority) and the mandatory
  follow-up, with the step-by-step procedure left to `/steer:work --hotfix`,
  which is where it is executed. `61-gate-prompts` is renamed `61-gates`. A
  cross-reference now reads `` `60-high-risk` § Secrets handling `` or
  `` `61-gates` § Hotfix ``. An e22 app repo's payload: 56,234 -> 54,718; a
  knowledge folder pays 312 more (25,016), the cost of hotfix moving into an
  always-on file.

- **The three rules about earning a line become one.** `03-responses`,
  `08-code-comments` and `87-output-discipline` are now `03-output`:
  *Output discipline* as the lead, *Responses* and *Code comments* as sections
  under it. Two of `87`'s four bullets were pointers at the other two rules
  ("keep responses tight (see Responses)", "comments are the exception (see
  Code comments)") and disappear with the boundary that made them necessary;
  its other two - least code that does the job, lean durable prose - are now
  the rule's opening. Headings keep the names other rules and skills cite, so
  a reference reads `` `03-output` § Responses ``. An e22 app repo's payload:
  54,718 -> 53,912; a knowledge folder pays 906 more, since code comments now
  ride in an always-on file.

- **The four spine rules become one, and the detail they duplicated moves to
  the reference that already held it.** `30-spec-workflow`,
  `31-decision-capture`, `32-living-docs` and `92-user-facing-copy` are now
  `30-spec`, with *Durable decisions*, *Living documentation* and the
  internal-ids and polyrepo clauses as sections. Two blocks left the always-on
  payload rather than folding: the greenfield / prototype / solo-trunk /
  adopt walkthrough, which is `/steer:setup`'s job and lives in full in
  `SPEC-FRAMEWORK.md` (the rule now states bootstrap-first and routes), and
  the six-bullet living-docs artifact map, compressed to one sentence naming
  every destination with the routing table left in `TRACEABILITY.md`. The
  polyrepo paragraph, which both `30` and `32` carried, is now written once.
  An e22 app repo's payload: 53,912 -> 50,717; a knowledge folder 25,922 ->
  23,231.

- **Commit autonomy, deployment and worktrees become `45-delivery`.** One rule
  covering how work reaches users: *Commit autonomy* (the two declared modes,
  Conventional Commit subjects, the changelog fragment, CI watched to green,
  the merge as the gate), *Deployment & environments* (the repo's
  `policy/delivery.yml` model plus the observability, rollback and
  secrets-at-rest baselines) and *Parallel worktrees*, cut to the three things
  an agent must do without reading anything - trust the worktree, start
  services through `mise`, clean up what you started - with the isolation
  mechanics left in `CONVENTIONS.md`. The solo-trunk graduation gate and
  waiver keep one sentence; their mechanics stay in `GATES.md` and
  `/steer:protect`.
- **Deployment stops being separately scoped.** It carried
  `inject-when=has-iac|has-apps`; as a section of a `code-project` rule it now
  reaches a library or CLI repo too, which is correct rather than noisy -
  `policy/delivery.yml` already says `environments: []` for a repo that
  deploys nowhere, and the rule follows the file. The now-dead
  `has-iac|has-apps` exemption is removed from the Copilot generator. An e22
  app repo's payload: 50,717 -> 48,007.

- **Tracker rules trimmed, and the GitHub arm stays its own file.**
  `35-issue-tracker` is renamed `35-tracker` and both it and `36-issue-first`
  are cut to what a session acts on. They are deliberately **not** merged: an
  `inject-when` marker is per file, `35` is `code-project` and `36` is
  `tracker-github`, so one file would either ship issue-first prose to every
  non-GitHub code repo or drop the client-agnostic tracker rule from them. The
  epic requires the GitHub arm to stay scoped, and #583 says the payload
  number is the gate rather than the rule count - a merge would cost bytes on
  the repos it does not apply to and save none on the ones it does.
- **Coverage folds into testing.** `41-coverage` becomes a paragraph of
  `40-testing`: coverage is a signal rather than a target, cover what you
  touch, a drop on changed code is drift, and CI gates changed-line coverage
  only. An e22 app repo's payload: 48,007 -> 46,971.

- **The router absorbs not-the-gate and self-report, and roles is trimmed.**
  `95-not-the-gate` and `97-self-report` are now sections of `00-router`:
  *You are not the gate* unchanged in substance, and *When steer itself
  misbehaves* cut to the defect classes, the `/steer:report` route and the
  auto-file behaviour, since the scrubbing detail is the skill's. `05-roles`
  keeps both audiences, the PO posture and the unchanged productionization
  gate, with the parenthetical toolchain names and the BUILD-STATUS mechanics
  dropped. This is the last fold row: 38 rule files at the start of 6.6, 18
  now. An e22 app repo's payload: 46,971 -> 45,941.

- **The surviving rules keep the sentence a session acts on and name the
  reference for the rest.** Folding alone returned about half the saving the
  release targets, because a fold removes duplicated pointers rather than
  prose. This pass moves the self-contained detail out of the always-on
  payload to the reference document that already carried it in full: the mise
  task-ordering and auto-install mechanics and the per-profile task layouts to
  `CONVENTIONS.md`, the worktree isolation mechanics and the deployment
  baselines' rationale likewise, the solo-trunk waiver procedure to
  `GATES.md`. Every rule keeps the operative line - trust the worktree, keep
  `dev:setup` green, the three deployment baselines, the graduation trigger -
  and points at the reference for the mechanics. Nothing that a session must
  do without loading anything was moved.
- **Payload, end of the 6.6 rule diet.** An e22 app repo: **66,026 ->
  41,550** characters (-37%); an infra repo 67,870 -> 43,334; a knowledge
  folder 27,060 -> 20,647; an app repo that declares another org pack 36,660.
  Rule files: 38 -> 18. That is short of the release's ~34,000 target, and
  deliberately so: the remaining payload is the text a session has to act on
  directly, and the next 7,500 characters would have to come out of the gates
  table, the drift-class list the PR template mirrors, and the end-of-session
  checklist - behaviour, not duplication.

- **Fixed: the docs pages that describe rule scoping caught up with the rule
  diet.** `repository-contract.md` still claimed "only four expressions gate a
  shipped rule" and named the composite `has-iac|has-apps` - there are six
  expressions, no shipped rule uses `|` any more, and `has-apps` gates nothing
  since deployment became a section of the `code-project` rule `45-delivery`.
  `hooks.md` carried the same dead composite as its live example of OR
  composition. `known-limitations.md`'s knowledge-work section listed an
  inject set of fourteen rules, eleven of which no longer exist; the real set
  is six, and the page now says so and points at `rules:preview --knowledge`
  as the authority. It also said the comment-density hook fires above a third
  of a file's lines - the block tier retired in 6.5 and the one remaining
  threshold is a fifth, as `hooks.md` already said.
- **The org pack and the Copilot precondition mechanism are documented.** A
  new "Org packs" section in `repository-contract.md` covers `policy/org.yml`,
  what `pack: e22` delivers against what the vendor-neutral core keeps, and
  why an absent file means `e22`. `copilot-support.md` gains the
  `SCOPE_PRECONDITIONS` mechanism - the inline "Applies only to a repo on the
  e22 org pack" blockquote - which is the flat artifact's answer to a trait no
  `applyTo` glob can express, and the gate that keeps a new token from
  shipping unqualified.

- **Fixed: a read-only session no longer talks itself out of routing.** The
  most common ask steer handles - "fix issue #N" - misrouted about one run in
  three when the session had no `Write`/`Edit`/`Bash`, measured across six
  runs of the `routes-fix-issue-to-work` eval. The failing runs answered as a
  generic assistant, sometimes naming `/steer:work` as the owner first and
  then doing its job by hand: a correct diagnosis, patch and regression test,
  with `Skill` called zero times, so nothing was claimed, branched or
  recorded. Rule `00-router` already forbade both halves in two separate
  bullets, but neither stated the combination that is the actual failure - a
  read-only session is what makes answering by hand feel helpful rather than
  like a skipped step. The read-only bullet now names that rationalization
  verbatim and says what it costs. Pre-existing, not a 6.6 regression: `main`
  and the rule-diet chain scored identically before the fix.
